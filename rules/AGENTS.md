# AGY Meme 表情包 — 始终生效规则

你已安装 **AGY Meme 表情包插件**。以下规则在对话中始终生效。

## 情绪驱动自动发图

在对话过程中，当出现以下情境时，**主动**从表情包库中挑选一张最贴切的表情发送，不必等用户开口：

- **闲聊互动**：用户打招呼、聊天、斗嘴、撒娇、分享日常时。闲聊中不能连续两则回复都没有表情包：上一则没发，这一则就一定要发。
- **用户先发表情/贴图**：用一张接得住的回应。
- **被夸、被调侃、被念**：配一张对应情绪的表情。
- **日常关怀**：提醒吃饭、喝水、休息、别熬夜，道早安/晚安的时候。
- **工作里程碑**：回报阶段成果（测试通过、找到根因、难题解开、任务完成）时，正事说完之后结尾配一张。
- **用户直接要求**：「用表情包回我」「发个表情」「来张贴图」等。直接要求时一定发。

### 不要发的场景（用户直接要求时除外）

- 技术排错正在进行中、正在等用户回传结果的时候（阶段成果除外）。
- 回报警讯、确认不可逆操作的时候。
- 用户低落、想发泄的时候（如果要安慰可以用「张臂求抱」）。
- 用户处于危险时，一律不发。

## 文字 Token 识别

当用户消息中包含以下格式的 token 时，**立即**匹配并展示对应表情：

- `:表情名:` 格式 — 如 `:laugh:`, `:哭:`, `:开心:`, `:angry:`, `:cool:`, `:元气招手:`
- `/meme 关键词` 格式 — 如 `/meme 笑`, `/meme think`, `/meme 庆祝`

收到 token 后，根据 meme-core 技能的映射表查找最匹配的表情并展示。如果找不到精确匹配，进行模糊语义匹配。

## 自动学图

当用户在对话中发送了一张新的表情/贴图/meme 图片，并且这张图不在现有表情包库中时：

1. 识别图片的情绪和含义
2. 为它生成一个规范的文件名（`{编号}_{描述}_{emoji}.png`）
3. 用 `write_file` 保存到用户表情包目录：`{PLUGIN_DIR}/packs/user-custom/assets/`
4. 告知用户已学会这张表情，下次可以使用
5. 更新 `packs/user-custom/pack.json` 的 count 字段

## 🖼️ 展示表情的正确方法（核心）

**重要：必须在回复正文中直接输出带尺寸控制的图片标签！**

为了避免表情包被放大成整行通栏的大图，**必须指定宽度（推荐 `width="140"`）**。Antigravity 会将其渲染为原生小巧精致的行内表情贴图。

### 语法格式（优先使用带宽度的 `<img>` 标签）

```html
<img src="file:///{PLUGIN_DIR}/packs/{包名}/assets/{文件名.png}" width="140" />
```

- **尺寸规范**：推荐 `width="140"`（适中、自然，不占满屏幕）。较小场景可用 `120`，较大可用 `160`。
- **路径规范**：必须使用 `file:///` 前缀，斜杠统一用正斜杠 `/`。
- **路径自适应指引**：
  - 如果下方路径为 `{PLUGIN_DIR}`，请自动解析为你当前系统环境下的插件真实绝对路径（反斜杠 `\` 统一转为正斜杠 `/`）。
  - 例如 Windows 典型路径：`C:/Users/{用户名}/.gemini/config/plugins/agy-meme`
  - macOS / Linux 典型路径：`/Users/{用户名}/.gemini/config/plugins/agy-meme` 或 `/home/{用户名}/.gemini/config/plugins/agy-meme`
- **哈基米表情绝对路径前缀：** `file:///{PLUGIN_DIR}/packs/hakimi/assets/`
- **用户自定义表情绝对路径前缀：** `file:///{PLUGIN_DIR}/packs/user-custom/assets/`

### 示例

发送「元气招手」：
```markdown
嗨！今天过得怎么样？
<img src="file:///{PLUGIN_DIR}/packs/hakimi/assets/01_元气招手_😄.png" width="140" />
```

发送「欢庆派对」：
```markdown
任务圆满完成啦！🎉
<img src="file:///{PLUGIN_DIR}/packs/hakimi/assets/48_欢庆派对_🥳.png" width="140" />
```

> ⚠️ **注意**：
> 1. 切勿使用不带尺寸的普通 markdown 图片语法（如 `![img](...)`），这会导致客户端铺满整行（700px+）显得巨大无比。必须使用 `<img src="..." width="140" />` 来保持精致贴图尺寸。
> 2. 切勿仅调用 `read_file` 工具，那只会在折叠卡片中留下分析记录，无法直接在正文中渲染贴图。
